## Общие вопросы по архитектуре

### 1. Какая архитектура используется в проекте?

**Ответ:** Проект использует архитектуру MVC (Model-View-Controller):
- **Model**: Entity классы (`Result.java`) и сервисы (`ResultService.java`) - работа с данными
- **View**: Facelets шаблоны (`index.xhtml`, `main.xhtml`) и JavaScript - представление
- **Controller**: Managed Beans (`PointBean`, `SessionBean`) - обработка запросов и бизнес-логика

### 2. Почему используется именно такая структура пакетов?

**Ответ:**
- `bean/` - Managed Beans для управления состоянием и обработки запросов
- `entity/` - JPA Entity классы для представления данных в БД
- `service/` - Сервисный слой для работы с БД (разделение ответственности)
- `util/` - Утилитарные классы без состояния
- `exception/` - Кастомные исключения для типизированной обработки ошибок

### 3. Какие технологии используются в проекте и зачем?

**Ответ:**
- **JSF 3.0** - компонентный фреймворк для веб-приложений, упрощает создание UI
- **CDI** - внедрение зависимостей и управление жизненным циклом бинов
- **JPA 3.1** - стандарт для работы с БД через ORM (объектно-реляционное отображение)
- **EclipseLink** - реализация JPA провайдера
- **H2 Database** - in-memory БД для простоты развертывания
- **BigDecimal** - для точных вычислений с длинными числами
- **HTML5 Canvas** - для динамической отрисовки графика

## Вопросы по JSF и Facelets

### 4. Что такое Facelets и чем они отличаются от JSP?

**Ответ:** Facelets - это система шаблонов для JSF, основанная на XML/XHTML. Отличия от JSP:
- Facelets компилируются в компонентное дерево JSF (более эффективно)
- JSP компилируются в сервлеты
- Facelets поддерживают композицию компонентов через `<ui:composition>`
- Facelets лучше интегрированы с JSF компонентами

### 5. Что означает `#{pointBean.x}` в XHTML?

**Ответ:** Это Expression Language (EL) выражение:
- `#{}` - deferred evaluation (вычисляется при каждом обращении)
- `pointBean` - имя Managed Bean (определено через `@Named("pointBean")`)
- `.x` - свойство бина (вызывает `getX()` при чтении, `setX(value)` при записи)
- JSF автоматически преобразует типы между String (из формы) и BigDecimal (в бине)

### 6. Зачем нужен `f:view` в XHTML?

**Ответ:** `<f:view>` - обязательная обертка для JSF страницы:
- Создает контекст JSF для страницы
- Инициализирует компонентное дерево
- Обрабатывает локализацию и кодировку
- Без него JSF компоненты не будут работать

### 7. Что делает `h:outputStylesheet` и как он работает?

**Ответ:** `h:outputStylesheet library="css" name="styles.css"`:
- Подключает CSS файл из `resources/css/styles.css`
- JSF автоматически генерирует правильный URL с версионированием
- `library` - папка в `resources/`
- `name` - имя файла
- В HTML генерируется: `<link rel="stylesheet" href="/web3/javax.faces.resource/styles.css.xhtml?ln=css">`

### 8. В чем разница между `h:link` и `h:commandLink`?

**Ответ:**
- **`h:link`** - обычная ссылка (GET запрос), не отправляет форму:
  - Используется для навигации: `<h:link outcome="main">`
  - Не вызывает методы бинов напрямую
  - Использует навигационные правила из `faces-config.xml`
  
- **`h:commandLink`** - ссылка, которая отправляет форму (POST запрос):
  - Может вызывать методы бинов: `<h:commandLink action="#{pointBean.setXValue(-4)}">`
  - Отправляет данные формы на сервер
  - Может использоваться с AJAX

### 9. Что такое `h:inputHidden` и зачем он нужен?

**Ответ:** `h:inputHidden` - скрытое поле формы:
- Не отображается визуально, но отправляется с формой
- Используется для X координаты: `<h:inputHidden id="xValue" value="#{pointBean.x}"/>`
- Заполняется JavaScript при клике на график
- Позволяет передать любое значение X (не только из списка)

## Вопросы по CDI и Managed Beans

### 10. Что такое CDI и зачем он нужен?

**Ответ:** CDI (Contexts and Dependency Injection) - стандарт для:
- **Dependency Injection** - автоматическое внедрение зависимостей через `@Inject`
- **Управление жизненным циклом** - создание и уничтожение объектов
- **Scopes** - области видимости бинов (Application, Session, View, Request)

### 11. В чем разница между `@ApplicationScoped`, `@SessionScoped` и `@ViewScoped`?

**Ответ:**
- **`@ApplicationScoped`** (`ClockBean`, `ResultService`):
  - Один экземпляр на все приложение
  - Создается при старте, уничтожается при остановке
  - Используется для общих данных и сервисов
  
- **`@SessionScoped`** (`SessionBean`):
  - Один экземпляр на сессию пользователя
  - Живет пока открыта сессия (обычно до закрытия браузера)
  - Используется для данных пользователя (список результатов)
  
- **`@ViewScoped`** (`PointBean`):
  - Один экземпляр на страницу
  - Сохраняет состояние между AJAX запросами на той же странице
  - Уничтожается при переходе на другую страницу
  - Используется для формы ввода (координаты точки)

### 12. Как работает `@Inject`?

**Ответ:** `@Inject` - аннотация для внедрения зависимостей:
```java
@Inject
private SessionBean sessionBean;
```
- CDI контейнер автоматически создает и внедряет `SessionBean`
- Не нужно создавать объект вручную: `new SessionBean()`
- Упрощает тестирование (можно заменить на mock)
- Управляет жизненным циклом зависимостей

### 13. Зачем нужен `@PostConstruct`?

**Ответ:** `@PostConstruct` - метод вызывается после создания бина и внедрения зависимостей:
```java
@PostConstruct
public void init() {
    loadResults(); // Загрузить данные из БД
}
```
- Используется для инициализации (загрузка данных, подключение к БД)
- Вызывается автоматически CDI контейнером
- Гарантирует, что все зависимости уже внедрены

### 14. Почему `PointBean` реализует `Serializable`?

**Ответ:** `Serializable` требуется для `@ViewScoped` бинов:
- JSF сохраняет состояние ViewScoped бина между запросами
- Состояние сериализуется и сохраняется в view state
- Позволяет восстановить состояние после AJAX запроса
- Без `Serializable` будет ошибка при сохранении состояния

## Вопросы по JPA и базе данных

### 15. Что такое JPA и зачем он нужен?

**Ответ:** JPA (Java Persistence API) - стандарт для работы с БД:
- **ORM** (Object-Relational Mapping) - отображение Java объектов на таблицы БД
- Не нужно писать SQL вручную (хотя можно через `@NamedQuery`)
- Автоматическое управление связями между объектами
- Портативность между разными БД

### 16. Что делает `@Entity` и `@Table`?

**Ответ:**
- `@Entity` - помечает класс как JPA сущность (будет отображена на таблицу БД)
- `@Table(name = "results")` - имя таблицы в БД (если не указано, используется имя класса)

### 17. Зачем нужен `@NamedQuery`?

**Ответ:** `@NamedQuery` - предопределенный именованный запрос:
```java
@NamedQuery(name = "Result.findAll", 
            query = "SELECT r FROM Result r ORDER BY r.timestamp DESC")
```
- Запрос компилируется один раз при загрузке класса (быстрее)
- Можно переиспользовать: `entityManager.createNamedQuery("Result.findAll", Result.class)`
- Легче поддерживать (запрос в одном месте)

### 18. Что такое `EntityManager` и как он работает?

**Ответ:** `EntityManager` - интерфейс для работы с БД:
- `persist(result)` - добавить объект в контекст персистентности (подготовить к сохранению)
- `flush()` - выполнить SQL запросы немедленно
- `createNamedQuery()` - выполнить именованный запрос
- `getResultList()` - получить результаты запроса

### 19. Почему используется `RESOURCE_LOCAL` вместо `JTA`?

**Ответ:** `transaction-type="RESOURCE_LOCAL"` в `persistence.xml`:
- Управление транзакциями вручную через `EntityTransaction`
- Подходит для простых приложений без контейнера транзакций
- `JTA` требует контейнер транзакций (более сложная настройка)
- Для H2 in-memory БД `RESOURCE_LOCAL` достаточно

### 20. Как работает транзакция в `ResultService.save()`?

**Ответ:**
```java
EntityTransaction tx = entityManager.getTransaction();
try {
    if (!tx.isActive()) {
        tx.begin();  // Начать транзакцию
    }
    entityManager.persist(result);  // Подготовить к сохранению
    entityManager.flush();         // Выполнить SQL
    if (tx.isActive()) {
        tx.commit();  // Подтвердить изменения
    }
} catch (Exception e) {
    if (tx.isActive()) {
        tx.rollback();  // Откатить при ошибке
    }
}
```
- `begin()` - начало транзакции
- `persist()` - добавляет объект в контекст (еще не в БД)
- `flush()` - выполняет SQL INSERT
- `commit()` - подтверждает изменения (делает их постоянными)
- `rollback()` - откатывает изменения при ошибке

### 21. Зачем нужен `@PreDestroy` в `ResultService`?

**Ответ:** `@PreDestroy` вызывается перед уничтожением бина:
```java
@PreDestroy
public void destroy() {
    entityManager.close();
    emf.close();
}
```
- Закрывает соединения с БД
- Освобождает ресурсы
- Предотвращает утечки памяти

## Вопросы по JavaScript и Canvas

### 22. Как работает отрисовка графика на Canvas?

**Ответ:**
1. `initCanvas()` - получает элемент canvas и контекст 2D
2. `drawArea()` - рисует область:
   - Очищает canvas: `ctx.clearRect(0, 0, canvas.width, canvas.height)`
   - Рисует оси: `ctx.beginPath()`, `ctx.moveTo()`, `ctx.lineTo()`, `ctx.stroke()`
   - Рисует фигуры: `ctx.rect()`, `ctx.arc()`, `ctx.fill()`
3. `drawPoints()` - рисует точки из результатов
4. `drawTicks()` - рисует засечки и подписи на осях

### 23. Как преобразуются координаты при клике на график?

**Ответ:**
```javascript
var rect = canvas.getBoundingClientRect();
var x = event.clientX - rect.left;  // Координата клика относительно canvas
var y = event.clientY - rect.top;

var centerX = 250;  // Центр canvas
var centerY = 250;
var scale = 100 / currentR;  // Масштаб (пикселей на единицу)

var realX = (x - centerX) / scale;  // Преобразование в реальные координаты
var realY = (centerY - y) / scale;  // Инвертируем Y (canvas Y растет вниз)
```
- `getBoundingClientRect()` - позиция canvas относительно viewport
- `event.clientX - rect.left` - координата относительно canvas
- `(x - centerX) / scale` - преобразование пикселей в единицы координат
- `centerY - y` - инвертирование Y (в canvas Y растет вниз, в математике - вверх)

### 24. Зачем нужен объект `pointsByRadius`?

**Ответ:** `pointsByRadius = {"1.0": [{x, y, hit}, ...], "1.5": [...]}`:
- Хранит точки для каждого радиуса отдельно
- При смене радиуса график очищается и показываются только точки для нового радиуса
- При возврате к предыдущему радиусу точки восстанавливаются
- Структура: ключ - радиус (строка), значение - массив точек

### 25. Как работает функция `loadPointsFromTable()`?

**Ответ:**
1. Находит таблицу результатов в DOM: `document.querySelector('.results-table')`
2. Перебирает строки таблицы (пропуская заголовок)
3. Извлекает X, Y, R, hit из ячеек: `cells[0].textContent.trim()`
4. Фильтрует по текущему радиусу: `Math.abs(r - currentR) < 0.001`
5. Сохраняет в `pointsByRadius[rKey]`

### 26. Почему используется `setTimeout()` в JavaScript?

**Ответ:** `setTimeout(function, delay)` - задержка выполнения:
- Гарантирует, что DOM обновлен после AJAX запроса
- Позволяет выполнить код в правильном порядке
- Используется для перерисовки canvas после обновления таблицы
- Пример: `setTimeout(redrawCanvas, 300)` - перерисовать через 300мс

### 27. Зачем нужен `typeof` проверки?

**Ответ:** `typeof function === 'function'` - проверка существования функции:
```javascript
if (typeof loadPointsFromTable === 'function') {
    loadPointsFromTable();
}
```
- Защита от ошибок, если функция не загружена
- Полезно при AJAX обновлениях (функции могут быть недоступны)
- Предотвращает `ReferenceError: function is not defined`

## Вопросы по AJAX

### 28. Как работает AJAX в JSF?

**Ответ:** `f:ajax` - компонент для AJAX запросов:
```xml
<f:ajax execute="pointForm" render="resultsForm:resultsPanel pointFormMessages"/>
```
- `execute` - какие компоненты отправить на сервер
- `render` - какие компоненты обновить после ответа
- Отправляет только указанные данные (не всю страницу)
- Обновляет только указанные части DOM (без перезагрузки)

### 29. В чем разница между `execute="@this"` и `execute="pointForm"`?

**Ответ:**
- `execute="@this"` - отправить только этот компонент (например, только поле Y)
- `execute="pointForm"` - отправить всю форму (все поля)
- `@this` - специальное ключевое слово JSF для текущего компонента

### 30. Что означает `render="resultsForm:resultsPanel"`?

**Ответ:** `resultsForm:resultsPanel` - полный ID компонента:
- `resultsForm` - ID формы
- `:` - разделитель (JSF генерирует ID как `formId:componentId`)
- `resultsPanel` - ID панели внутри формы
- JSF обновит только этот компонент после AJAX запроса

### 31. Как работает `jsf.ajax.addOnEvent()`?

**Ответ:** Глобальный обработчик всех AJAX событий:
```javascript
jsf.ajax.addOnEvent(function(data) {
    if (data.status === 'success') {
        // Код после успешного AJAX запроса
    }
});
```
- Вызывается для каждого AJAX запроса
- `data.status` - статус: 'begin', 'success', 'error', 'complete'
- Используется для перерисовки canvas после обновления таблицы

## Вопросы по валидации и обработке ошибок

### 32. Как работает валидация в JSF?

**Ответ:** Валидация на нескольких уровнях:
1. **HTML5 валидация**: `required="true"` - браузер проверяет перед отправкой
2. **JSF валидаторы**: `validator="#{pointBean.validateY}"` - кастомный валидатор
3. **Серверная валидация**: в методе `checkPoint()` проверяются все поля

### 33. Что делает кастомный валидатор `validateY()`?

**Ответ:**
```java
public void validateY(FacesContext context, UIComponent component, Object value) 
        throws ValidatorException {
    BigDecimal yValue = new BigDecimal(strValue);
    if (yValue.compareTo(MIN_Y) < 0 || yValue.compareTo(MAX_Y) > 0) {
        throw new ValidatorException(new FacesMessage(...));
    }
}
```
- Вызывается JSF автоматически при валидации поля
- Проверяет диапазон значений (-5 до 3)
- `ValidatorException` - JSF покажет сообщение пользователю
- Сообщение отображается в `<h:message for="yValue">`

### 34. Как работает централизованная обработка ошибок?

**Ответ:** `ErrorHandler` - утилита для обработки ошибок:
```java
public static void handleError(Exception e, String userMessage) {
    FacesContext context = FacesContext.getCurrentInstance();
    context.addMessage(null, new FacesMessage(
        FacesMessage.SEVERITY_ERROR, "Ошибка", userMessage));
    logger.log(Level.SEVERE, "Ошибка: " + userMessage, e);
}
```
- Единая точка обработки ошибок
- Разделяет сообщения для пользователя и технические (для логов)
- `context.addMessage(null, ...)` - глобальное сообщение (показывается в `h:messages`)

### 35. Как отображаются ошибки пользователю?

**Ответ:** Ошибки показываются в двух местах:
1. **В tooltip по центру экрана**: JavaScript `showErrorInTooltip()` читает сообщения из DOM
2. **В `h:messages`**: JSF автоматически показывает `FacesMessage`
3. **Под полями**: `<h:message for="yValue">` показывает ошибки конкретного поля

## Вопросы по BigDecimal и точности

### 36. Почему используется `BigDecimal` вместо `double`?

**Ответ:**
- **`double`** - числа с плавающей точкой, ограниченная точность (15-17 знаков)
- **`BigDecimal`** - произвольная точность (50 знаков в проекте)
- `double` может терять точность: `0.1 + 0.2 != 0.3` (проблема округления)
- `BigDecimal` сохраняет точность для длинных чисел

### 37. Как работает `MathContext` в `AreaChecker`?

**Ответ:**
```java
private static final MathContext MATH_CONTEXT = new MathContext(50, RoundingMode.HALF_UP);
BigDecimal result = x.multiply(y, MATH_CONTEXT);
```
- `MathContext(50, RoundingMode.HALF_UP)` - точность 50 знаков, округление вверх
- Все операции с `BigDecimal` используют этот контекст
- Гарантирует одинаковую точность во всех вычислениях

### 38. Почему используется `compareTo()` вместо `==` для `BigDecimal`?

**Ответ:**
- `==` сравнивает ссылки на объекты (не значения)
- `compareTo()` сравнивает значения:
  - `x.compareTo(y) < 0` - x < y
  - `x.compareTo(y) == 0` - x == y
  - `x.compareTo(y) > 0` - x > y

### 39. Как `BigDecimal` передается между клиентом и сервером?

**Ответ:**
1. **Клиент → Сервер**: JavaScript передает строку: `xInput.value = x.toString()`
2. **JSF преобразует**: String → BigDecimal через сеттер `setX(String xStr)`
3. **Сервер → Клиент**: BigDecimal → String через геттер `getX()` и EL `#{result.x}`
4. **В БД**: `@Column(precision=50, scale=30)` - хранится как DECIMAL(50,30)

## Вопросы по конкретным решениям

### 40. Почему график перерисовывается после каждого AJAX запроса?

**Ответ:** JSF может пересоздать canvas элемент при AJAX обновлении:
- Canvas теряет контекст рисования
- Нужно переинициализировать: `canvas = document.getElementById('areaCanvas')`
- Перерисовать график: `drawArea()`
- Восстановить обработчик клика: `setupCanvasClickHandler()`

### 41. Зачем нужен polling (опрос) таблицы результатов?

**Ответ:** `setInterval()` проверяет изменения таблицы каждые 500мс:
- Fallback механизм, если AJAX обновление не сработало
- Отслеживает количество строк: `resultsTable.rows.length`
- Если изменилось - перерисовывает график
- Гарантирует синхронизацию графика с таблицей

### 42. Почему используется `h:inputHidden` для X, а не `h:inputText`?

**Ответ:**
- X может быть любым значением (при клике на график)
- Не должен вводиться вручную (только через график или кнопки)
- `h:inputHidden` - скрытое поле, не отображается, но отправляется с формой
- JavaScript заполняет его при клике на график

### 43. Зачем нужны множественные `setTimeout()` с разными задержками?

**Ответ:** Последовательное выполнение операций:
```javascript
setTimeout(function() { updateXSelection(); }, 100);   // Сначала обновить выделение
setTimeout(function() { loadPointsFromTable(); }, 300); // Потом загрузить точки
setTimeout(function() { redrawCanvas(); }, 500);        // Затем перерисовать
```
- Гарантирует правильный порядок выполнения
- Каждая операция ждет завершения предыдущей
- Предотвращает гонки условий (race conditions)

### 44. Почему используется `RESOURCE_LOCAL` транзакции вместо контейнерных?

**Ответ:**
- `RESOURCE_LOCAL` - управление транзакциями вручную через `EntityTransaction`
- Проще для простых приложений
- Не требует настройки контейнера транзакций (JTA)
- Для H2 in-memory БД достаточно
- Контейнерные транзакции (JTA) нужны для распределенных систем

### 45. Как работает навигация между страницами?

**Ответ:** Навигация через `faces-config.xml`:
```xml
<navigation-rule>
    <from-view-id>/index.xhtml</from-view-id>
    <navigation-case>
        <from-outcome>main</from-outcome>
        <to-view-id>/main.xhtml</to-view-id>
    </navigation-case>
</navigation-rule>
```
- Метод бина возвращает строку: `return "main";`
- JSF ищет правило навигации для текущей страницы
- Находит `from-outcome="main"` и переходит на `/main.xhtml`
- `h:link outcome="main"` также использует это правило

### 46. Зачем нужен `@Named` на бинах?

**Ответ:** `@Named("pointBean")` - регистрирует бин в CDI:
- Делает бин доступным в Expression Language: `#{pointBean.x}`
- Без `@Named` бин не будет доступен в XHTML
- Имя в скобках - имя для EL (если не указано, используется имя класса)

### 47. Почему `ResultService` - `@ApplicationScoped`, а не `@RequestScoped`?

**Ответ:**
- `@ApplicationScoped` - один экземпляр на все приложение
- `EntityManagerFactory` создается один раз (дорогая операция)
- Переиспользуется для всех запросов (эффективнее)
- `@RequestScoped` создавал бы новый `EntityManagerFactory` для каждого запроса (неэффективно)

### 48. Как работает проверка попадания точки в область?

**Ответ:** `AreaChecker.checkHit(x, y, r)` проверяет три условия:
1. **Прямоугольник** (2-я четверть): `-R/2 <= x <= 0 && 0 <= y <= R`
2. **Треугольник** (1-я четверть): `0 <= x <= R/2 && 0 <= y <= R && y <= R - 2x`
3. **Четверть круга** (3-я четверть): `x <= 0 && y <= 0 && x² + y² <= R²`
- Если точка попадает хотя бы в одну область - возвращает `true`

### 49. Зачем нужен `@Column(precision=50, scale=30)`?

**Ответ:**
- `precision=50` - всего 50 цифр в числе
- `scale=30` - 30 цифр после запятой
- Позволяет хранить очень длинные числа с высокой точностью
- В БД создается тип `DECIMAL(50,30)`

### 50. Как работает обновление часов на index.xhtml?

**Ответ:**
1. Сервер рендерит начальное время: `#{clockBean.currentDateTime}`
2. JavaScript `updateClock()` обновляет время каждые 6 секунд
3. `setInterval(updateClock, 6000)` - вызывает функцию каждые 6000мс
4. Обновляет DOM напрямую: `clockElement.textContent = ...`
5. Не использует AJAX (обновление только на клиенте)

## Дополнительные вопросы для глубокого понимания

### 51. Что произойдет, если удалить `@ViewScoped` с `PointBean`?

**Ответ:** Бин станет `@RequestScoped` (по умолчанию):
- Состояние (x, y, r) будет теряться после каждого запроса
- При AJAX обновлении поля будут сбрасываться
- Пользователь не сможет заполнить форму пошагово

### 52. Почему используется `h:dataTable` вместо обычной HTML таблицы?

**Ответ:**
- `h:dataTable` - JSF компонент, интегрирован с бинами
- Автоматически обновляется при AJAX запросах
- Поддерживает пагинацию, сортировку (если нужно)
- Легче поддерживать (изменения в бине автоматически отражаются)

### 53. Что будет, если не использовать `flush()` в `ResultService.save()`?

**Ответ:**
- `persist()` только добавляет объект в контекст персистентности
- SQL запрос может не выполниться сразу
- При чтении результатов новый объект может не появиться
- `flush()` принудительно выполняет SQL запросы

### 54. Зачем нужен `serialVersionUID` в классах?

**Ответ:** `private static final long serialVersionUID = 1L;`
- Требуется для `Serializable` классов
- Версия сериализованного объекта
- При изменении класса нужно обновить версию
- Предотвращает ошибки десериализации

### 55. Почему используется `LocalDateTime` вместо `Date`?

**Ответ:**
- `LocalDateTime` - современный API (Java 8+)
- Не имеет проблем с часовыми поясами (в отличие от `Date`)
- Более удобный API для работы с датами
- Лучше интегрируется с JPA

## Вопросы на понимание потока выполнения

### 56. Опишите полный цикл: пользователь кликает на график → результат в таблице

**Ответ:**
1. Пользователь кликает на canvas
2. JavaScript `handleCanvasClick()` вычисляет координаты клика
3. Преобразует в реальные координаты (X, Y)
4. `submitPoint(x, y)` устанавливает значения в скрытые поля
5. Программно нажимает кнопку "Отправить": `checkButton.click()`
6. JSF отправляет AJAX запрос с данными формы
7. Вызывает `pointBean.checkPoint()`
8. Валидация полей (X, Y, R)
9. `AreaChecker.checkHit(x, y, r)` - проверка попадания
10. Создание `Result` объекта
11. `sessionBean.addResult(result)` - сохранение
12. `resultService.save(result)` - транзакция в БД
13. `sessionBean.loadResults()` - перезагрузка списка
14. JSF возвращает AJAX ответ
15. JavaScript обновляет таблицу результатов
16. `loadPointsFromTable()` - загружает точки из таблицы
17. `redrawCanvas()` - перерисовывает график с новой точкой

### 57. Что происходит при смене радиуса R?

**Ответ:**
1. Пользователь выбирает новое значение в `h:selectOneMenu`
2. `f:ajax event="change"` отправляет AJAX запрос
3. JSF вызывает `pointBean.setR(String rStr)`
4. JavaScript `handleRadiusChange()` вызывается
5. Обновляется `currentR`
6. `loadPointsFromTable()` - загружает точки для нового радиуса (фильтрует по R)
7. `drawArea()` - перерисовывает график с новым масштабом
8. Старые точки для предыдущего радиуса скрываются
9. Показываются только точки для нового радиуса
